## FolderView Plus 2026.08.11.02

This development build removes the Settings global-action bottleneck while preserving the existing declarative event and Unraid host compatibility contracts.

### Registry-owned actions

- Refactor: Move all 145 Settings actions from broad `window` publication into the owner-scoped declarative action registry.
- Reliability: Resolve registered handlers before legacy host globals, reject invalid registrations and cross-owner collisions atomically, and release Settings-owned actions during page teardown.
- Compatibility: Keep the legacy global fallback for current Docker, VM, Dashboard, Folder Editor, and Unraid host actions while reducing measured browser globals from 509 to 375.
- Quality: Route the recovery diagnostics workspace through the action registry instead of a direct Settings global.

### Enforcement and regression coverage

- Quality: Ratchet the action architecture to at least 145 registered actions, no more than 11 registry/global overlaps, and a maximum of 375 browser globals.
- Quality: Reject the retired broad `registerWindowActions` helper and require every static or generated declarative action to have a registry, plugin compatibility, or documented Unraid host owner.
- Quality: Add module contracts and line budgets for the action runtime and Settings action-support module, reducing the uncontracted browser-script inventory from 100 to 98.
- Security: Add registry precedence, teardown, validation, collision, and atomic-failure tests while keeping CSP source checks at zero inline events, inline scripts, and style attributes.
