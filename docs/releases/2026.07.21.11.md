# FolderView Plus 2026.07.21.11

This stable release contains every change made on `dev` since stable `2026.07.19.17`. It delivers a responsive Dashboard layout overhaul, a redesigned Dashboard action rail, substantially faster and safer Settings startup, lighter Diagnostics, stronger preference persistence and telemetry, and more reliable release operations.

## Features

- Feature: Rework Compact Matrix into a responsive Dashboard layout that selects one, two, or three folder columns from the actual Docker or VM widget width instead of the full browser viewport.
- Feature: Redesign the Docker and VM Dashboard action rail around four focused controls: layout, expand or collapse all, running-only filtering, and a consolidated View options menu.
- Feature: Add a named Dashboard layout selector covering Classic, Legacy, Full Width, Accordion, Inset, Compact Matrix, and Embossed without requiring users to cycle blindly through layouts.
- Feature: Add a compact Dashboard View options popover containing Running only, Health emphasis, Compact density, Reset view, and a direct link to Settings.
- Feature: Add one combined Settings configuration snapshot that returns saved Docker and VM folders and preferences through a single request.
- Feature: Add a lightweight Diagnostics support-preview contract endpoint so the preview can describe an export without building the full support bundle.

## UI/UX

- UI/UX: Keep Compact Matrix member tiles readable at narrow widths and truncate unavoidable long labels cleanly instead of clipping their contents.
- UI/UX: Increase Dashboard action target sizes on desktop and mobile, provide clear selected and pending states, and collapse narrow widgets to the essential expand and View options controls.
- UI/UX: Replace the seven Dashboard layout buttons in View options with one compact, themed native dropdown.
- UI/UX: Use neutral theme-token colors for Dashboard layout, display, reset, and settings controls instead of inherited orange button text, borders, and fills.
- UI/UX: Remove inherited Dashboard popover button margins and reduce layout, display, and footer gaps to make the menu substantially more compact.
- UI/UX: Add a compact Settings first-paint loading shell and reveal the workspace only after its saved mode, tab, folder configuration, and preferences are ready, eliminating the flash of the raw Advanced page.
- UI/UX: Show neutral loading or unavailable states for folder status and Docker signal cells until live runtime hydration completes instead of briefly presenting members as stopped.
- UI/UX: Keep saved Docker and VM folder tables visible and usable while optional version, release-note, theme, Diagnostics, and live runtime data load independently.

## Accessibility

- Accessibility: Add explicit pressed and selected semantics, visible keyboard focus, arrow-key Dashboard layout navigation, Escape and outside-click dismissal, and trigger focus restoration.
- Accessibility: Keep the Dashboard layout selector on native keyboard navigation with a localized accessible label and a disabled state while a selection is being saved.
- Accessibility: Preserve touch-friendly action targets and safe behavior when Dashboard widgets become too narrow for the full action rail.

## Performance

- Performance: Use the measured Dashboard widget width, per-widget resize observation, and orientation reconciliation so Compact Matrix updates after panel resizing, Dashboard rearrangement, or mobile rotation without a refresh.
- Performance: Load each Settings Docker and VM core state through coherent snapshots instead of separate folder, preference, and runtime request chains.
- Performance: Paint both saved Docker and VM folder tables in one browser pass from the combined configuration snapshot.
- Performance: Use a runtime-free Settings configuration path so first paint never waits for Docker inspection or libvirt discovery.
- Performance: Hydrate Docker and VM runtime details independently in the background so a slow or unavailable VM response cannot delay Docker folders.
- Performance: Stop plugin version lookup, release notes, theme workspace data, and inactive Advanced-tab datasets from blocking the core Settings interface.
- Performance: Remove passive theme-resolution and reflow events from the server diagnostics mutation path so initial styling no longer creates a competing request burst.
- Performance: Skip unchanged theme-token CSS properties and attributes, preventing a MutationObserver feedback loop from repeatedly rendering Settings during startup.
- Performance: Stop generating a full support-bundle preview on every Settings load and defer full host discovery, history collection, privacy redaction, and browser telemetry until a report is copied or exported.
- Performance: Deduplicate and briefly cache Diagnostics preview hydration so repeated Diagnostics navigation cannot create overlapping requests.
- Performance: Apply preference changes optimistically and coalesce rapid changes for 160 milliseconds.
- Performance: Avoid flash writes for no-op preference saves and skip full recovery backups, order reconciliation, and synchronous audit-history work for display-only preferences.
- Performance: Reuse a recent recovery checkpoint for repeated protected changes within 30 seconds while preserving the safety boundary for durable mutations.

## Fixes

- Fix: Correct Compact Matrix sizing inside narrow Dashboard panels on wide desktop viewports, including long German and other translated container names.
- Fix: Prevent Dashboard layout choices from being lost when Settings, the Dashboard quick switch, another tab, or an unrelated preference save writes nearby preference state.
- Fix: Prevent stale broad preference payloads from carrying an older Dashboard layout over a newer committed selection.
- Fix: Delay Dashboard layout application and Compact Matrix measurement until preference hydration and folder rendering are complete, so startup defaults and zero-width widgets cannot become authoritative.
- Fix: Make the Settings blank-page watchdog recognize the intentional startup shell, preventing false `FVPLUS-SET-BLANK-001` errors on slower refreshes while retaining the genuine stalled-bootstrap warning.
- Fix: Defer empty-folder, health, update, quick, and status filters until live runtime hydration is complete so rule-populated folders cannot disappear during first paint.
- Fix: Ensure full manual refresh and recovery workflows still wait for complete runtime state even though normal first paint now hydrates Docker and VM independently.
- Fix: Prevent Unraid global button styles from applying orange text and borders to the Dashboard View options menu.

## Reliability and persistence

- Reliability: Commit Dashboard layout changes as an isolated `dashboard.layout` mutation, verify the server-confirmed value, and surface a visible error if persistence returns a different selection.
- Reliability: Retain revision-conflict rebasing and cross-tab preference synchronization so Dashboard choices survive refreshes and Settings or Dashboard navigation.
- Reliability: Keep optimistic rollback and themed error feedback when Dashboard layout persistence fails.
- Reliability: Synchronize the currently saved layout into the selector every time the View options popover opens.
- Reliability: Preserve the existing Settings preference coordinator, pending-write replay, and metadata revisions when hydrating from snapshots.
- Reliability: Retain automatic per-type and legacy request fallbacks for mixed-version or partially cached installations.
- Reliability: Increase the warm runtime-cache window to avoid unnecessary host queries without weakening explicit refresh behavior.
- Reliability: Keep ordering, rules, start order, folder defaults, import presets, and backup schedules behind revision checks, atomic last-good writes, full recovery checkpoints, and mutation audit records.

## Diagnostics and observability

- Diagnostics: Add privacy-safe Dashboard geometry telemetry including measured widget width, folder and member column counts, row count, and estimated tile width for Docker and VM widgets.
- Diagnostics: Distinguish unmeasured, measured, and stale Dashboard layout telemetry states and retain the last valid geometry instead of replacing it with a transient zero-width result.
- Diagnostics: Report the committed Dashboard layout separately from temporary UI state and include a bounded, privacy-safe transition trace with source, revision, outcome, and timestamp.
- Diagnostics: Split Settings performance telemetry into configuration first paint, Docker runtime hydration, VM runtime hydration, full manual refresh, and Diagnostics refresh measurements with individual budgets.
- Diagnostics: Persist bounded Settings performance samples in browser storage for 24 hours across refreshes.
- Diagnostics: Limit current performance-health evaluation to samples from the latest 30 minutes so stale historical timings cannot create a present warning.
- Diagnostics: Keep full support-bundle generation available for Copy issue report and Export support bundle while using the lightweight contract for the on-page preview.

## CI and release engineering

- CI: Use shallow GitHub Actions checkouts for jobs that do not require tags, ancestry, or packaging history, reducing routine checkout time as the repository grows.
- CI: Retain full history only for version/history guards, preview packaging, stable packaging, release publishing, and main-to-dev backmerge operations that require it.
- Reliability: Grant the backmerge workflow explicit pull-request permission and support an optional `FVPLUS_BACKMERGE_TOKEN` for repositories that restrict pull-request creation by the default Actions token.
- Reliability: Create and update backmerge pull requests through the GitHub API with explicit error handling.
- Reliability: Fail the backmerge workflow with an actionable summary and manual comparison link if its validated branch is pushed but the pull request cannot be created or updated, instead of quietly reporting success while `dev` remains behind `main`.

## Compatibility and upgrade notes

- Compatibility: Existing Dashboard layouts and display preferences continue to use the same preference schema and are migrated through the normal verified preference path.
- Compatibility: The prior per-type Settings snapshot requests and legacy folder, preference, and runtime endpoints remain automatic fallbacks for cached or mixed-version pages.
- Compatibility: No manual configuration migration is required; saved folders, hierarchy, Dashboard choices, privacy settings, and recovery history remain intact.
