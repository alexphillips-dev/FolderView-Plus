## FolderView Plus 2026.08.11.15

This stable release promotes every validated development change since stable `2026.08.10.02`. It completes the planned monolith-reduction program, strengthens security and release controls, and includes the Docker, Diagnostics, popup, theme, localization, and editor corrections proven during development testing.

- Quality: Establish enforceable ownership, dependency, lifecycle, load-order, browser-global, inline-action, overlap, and non-increasing file-size contracts for primary browser and server entrypoints.
- Refactor: Move all 145 Settings actions from broad `window` publication into the owner-scoped declarative action registry with atomic collision rejection and teardown.
- Refactor: Split foundational scheduling, storage, escaping, identifier, URL sanitization, normalization, preferences, ordering, transfer, and runtime-rule utilities into focused modules while retaining the complete compatibility facade.
- Refactor: Split GraphQL request mechanics, subscription ownership, and Docker actions into transport modules while preserving stale-request rejection, abort behavior, reconnect limits, CSRF headers, and privacy-safe diagnostics.

- Refactor: Split Folder Editor regex selection, worker/debounce lifecycle, hierarchy, member rendering, drag ordering, preview bootstrap, page bootstrap, and runtime bootstrap into bounded modules while preserving saved-folder and nested-folder behavior.
- Refactor: Split Settings search plus Setup Wizard persistence and review modeling into focused modules with blocked-storage fallbacks and unchanged saved-preference behavior.
- Refactor: Decompose PHP release metadata, storage, themes, environment transfer, backups, folder rules and mutations, Docker ordering, runtime information, diagnostics, and custom-icon handling behind compatibility facades.
- Refactor: Split second-generation shared utility and Docker/VM/Dashboard runtime monoliths into normalization, preference, ordering, transfer, rule, primitive, diagnostics, and control modules.
- Refactor: Split the fixture-browser and browser-smoke runners by domain while preserving the original scenarios, assertions, browser matrix, artifacts, and test intent.
